# Design rationale doc

**Use when:** you need to document why a design is the way it is, for engineers, stakeholders, or future you

**You'll need:** the design (description or screens), key decisions, constraints

## Prompt

```text
Write a design rationale doc for [FEATURE].

The design: [DESCRIBE or link]
Key decisions I made: [LIST]
Constraints: [technical, business, timeline, accessibility, legal]

For each decision: the decision in one sentence, the options considered, why this one won, what we gave up, and what would make us revisit it.

Add a short "open questions" section and a "what's final versus still flexible" list so engineering knows what's safe to build on.

Keep it skimmable: one decision per heading, no history lesson.
```
